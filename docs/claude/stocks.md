# 個股資料（財報、籌碼、估值、低本益比、營收排行、創新高）

> 從專案根目錄的 CLAUDE.md 拆出來（2026-10-31）：CLAUDE.md 每次都整份載入，主題細節放這裡，改到這一塊時才讀。
> 什麼時候讀：改個股頁、fetch_stocks.py、fetch_pe.py、fetch_highs.py、估值／低本益比。

## 個股資料

`scripts/fetch_stocks.py`，來源全是官方免費端點，**不動用 FinLab 額度**。產出三份：

| 檔案 | 進版控？ | 誰產生 |
| --- | --- | --- |
| `app/public/data/fin_history.json` | **是** | 每日更新流程（`--no-chips`），它才會 commit |
| `.cache/stock_chips.json` | 否 | 部署流程，用 Actions 快取保存 |
| `app/public/data/stocks/*.json` | 否 | 部署流程，前端實際讀的（每檔約 600 bytes） |

三個一定要知道的資料性質：

- **財報端點只回當期**（本季、本月），沒有任何歷史參數。所以季度趨勢是逐期累積的，
  `fin_history.json` 進版控、每次執行合併、已有的期別不覆蓋。要一次補回幾年份只有
  用 FinLab 抓一次（吃額度）或對每家公司逐季查觀測站（兩萬多次請求，不做）。
- **季報是累計數**：季別 2 是上半年、季別 3 是前三季。台積電 2026Q2 營收 2.40 兆，
  而 1～8 月累計月營收 3.39 兆 —— 當成單季會差一倍。`singleQuarter()` 在有連續兩期
  時還原單季，畫面一律標「累計」。資產負債表是時點數，不受影響。
- **單位**：財報是千元（1 億元 = 100,000 千元、1 兆元 = 1,000,000,000 千元），
  買賣超是股，融資融券是張。`lib/stock.ts` 收斂換算，`tests/stock.test.ts` 用台積電
  的真實數字釘住 —— 這兩個常數寫錯十倍時畫面看起來仍然正常。

**觀測站的財報依產業分六種格式**（`_ci` 一般業、`_basi` 銀行、`_bd` 證券、`_fh` 金控、
`_ins` 保險、`_mim` 異業），欄位名稱各不相同。原本只抓 `_ci`，49 檔（多半是金融股）整格
「還沒有財報資料」。兩個陷阱：**金控那份的表頭比數值多一欄**，從第二欄起每個值都落在
下一個欄名底下（華南金的「淨收益」欄是 152 萬，實際 407 億）；保險業的「營業收入」
兜不出它自己的營業利益。所以 `merge_quarterly()` 用加總關係判斷對齊或錯位，
對不上的欄位留空，不照欄名硬取。存託憑證（DR）在觀測站沒有季報。

融資融券那兩張表把「前日餘額」排在「今日餘額」前面（上市 5/6、上櫃 2/6），
取錯一格會整頁顯示昨天的數字而且毫無異狀；第一版就取錯過，靠比對原始列才發現。

集保股權分散表一次 9 MB、68000 列，只留三個數字：400 張以上（分級 12–15）、
千張以上（分級 15）、股東人數（分級 17）。它每週更新，日期與買賣超不同天。

### 財務分析儀表板（杜邦 ROE 與經營效率）

`components/FundamentalsBoard.tsx`，計算在 `lib/fundamentals.ts`（純函式、`tests/fundamentals.test.ts`）。
跟上面的財報不同，這塊**不經過部署流程**：打開個股時由瀏覽器直接向 FinMind 抓那一檔的三張表
（`api/finmind.ts`）。全市場兩千檔 × 三張表要六千個請求，免費層一小時 300 次，部署時抓不完；
而使用者一次只看一檔，FinMind 回 `Access-Control-Allow-Origin: *`，額度算在瀏覽者自己的 IP。
CSP 的 `connect-src` 為此放行 `https://api.finmindtrade.com`。

三張表的期間不同，是最容易錯的地方：**損益表是單季、資產負債表是時點、現金流量表是年初累計**
（要減掉同年前一季；前一季缺就留 null，不把累計當單季）。這跟觀測站那份財報（累計、千元）
也不一樣 —— FinMind 的單位是元。

- 比率一律是 TTM 流量 ÷（本季與四季前的平均餘額）；四季不連續就不算 TTM。
- 杜邦恆等式 ROE = 淨利率 × 週轉率 × 權益乘數由測試盯著（台積電 2026Q2：40.6%）。
- 「ROE 變化來自哪一項」用對數分解（`dupontDrivers`），不用替代法 —— 替代法的答案跟替換順序有關。
- 金融業沒有營業成本與存貨，那些比率是 null、畫面寫「不適用」，不是 0。
- 面板刻意固定深色（站主要的「BI、科技感」），不跟主題切換；紅漲綠跌照舊，
  但天數與負債比是「越低越好」，所以那幾格變小顯示紅色。

### 估值：本益比／淨值比河流圖、預估本益比

`components/ValuationBoard.tsx`，計算在 `lib/valuation.ts`（`tests/valuation.test.ts`）。跟財務分析儀表板
一樣由瀏覽器向 FinMind 抓（`fetchValuation`，`TaiwanStockPER` 與 `TaiwanStockPrice` 兩個請求，2015 年起逐日）。

- **近四季 EPS 不另外抓財報**：收盤價 ÷ 交易所本益比反推（台積電 2026-10-30：2370 ÷ 27.47 = 86.28），
  口徑跟交易所一致。本益比 0 是近四季虧損，當成沒有、那段不畫河流。
- 河流 = 每月底的 EPS（或每股淨值）× 近 3／5／10 年本益比（淨值比）的第 10／25／50／75／90 百分位。
  有效天數不到 120 天不算百分位。景氣循環股獲利高峰時河流會衝到股價好幾倍（長榮 2022），
  圖的 Y 軸限制在收盤價範圍的一半到 2 倍，超出的裁掉。
- 金融股（`金融保險業`／`金融業`）與目前虧損的預設看淨值比；`CYCLICAL` 那幾個產業顯示「本益比容易失真」提示。
- **營收推估**：近 3 個月（不足就用有的）營收合計 ÷ 去年同期（由年增率反推）套到近四季 EPS，假設淨利率不變。
  月營收來自 `stocks/{code}.json` 的 `m`（累積式，剛上線時只有兩個月），不多打 FinMind。
  另可自己輸入 EPS。兩者都跟歷史「近四季」本益比分布比，畫面標「推估」。
- 沒有分析師共識 EPS：FactSet、CMoney 都要付費，新聞裡的調查數字不抓。

### 低本益比篩選

`stocks/pe.json`（`scripts/fetch_pe.py`，部署時產生，排在 `fetch_stocks.py` 後面）：證交所 `BWIBBU_ALL`／
`STOCK_DAY_ALL`、櫃買 `tpex_mainboard_peratio_analysis`／`daily_close_quotes` 的本益比與收盤，加上
`fin_history.json` 每檔近 3 個「可用」月營收。計算在 `lib/cheap.ts`（`tests/cheap.test.ts`），
**預估本益比直接呼叫 `revenueEstimate()`**，所以跟個股頁的營收推估一定同一個數字 —— 不要在 Python 另算一份。

- 本益比空白（近四季虧損）、不在公司清單（ETF、特別股）的不列。
- 預設排除：本期或基期月平均營收 < 1 億（建設股基期近零，坤悅 +2,630,241% → 0.0 倍）、
  營收年增 > 100%（淨利率不變不成立）、成交 < 1000 萬、金融股（月營收含投資損益，富邦金 −64%）。
  景氣循環股只標籤、不預設排除。
- 個股抽屜（`StockSheet`）也放了 `ValuationBoard`，從清單點一檔就看得到河流圖。

### 營收排行、創新高、類股成交比重

- **營收排行**（`stocks/ranking.json`）：全市場最新一個月，兩千檔一份，前端才排得動。
  **門檻同時套在本期與基期**：建設公司依完工比例認列，去年同月可能只有幾十萬，
  今年 8.9 億就是 +2,630,241%，會把整張榜洗掉。只擋本期營收沒有用 —— 它們的本期
  營收很大。`impliedBase()` 從成長率反推基期，兩期都要過門檻。
- **創新高與漲跌幅**（`highs.json`）：`fetch_highs.py` 用的兩份資料集正是 `fetch_calc.py`
  抓過的，同一次執行共用 `.cache/finlab_db`，所以**不會多花流量** —— 但單獨跑它會
  真的下載一次。高低點用**還原股價**算，不然 00631L 那類做過分割的會顯示「距高點
  -93%」；畫面顯示的股價則是原始收盤價。三個窗口（150／200／250 日）各存一組，
  漲跌幅是一週／一月／一季／半年（以交易日計，5／20／60／120 日），同樣用還原股價。
  期間不足的存 null 而不是 0 —— 新股上市首月常常大漲，混進半年榜會是誤導。
- **類股成交比重**（`chips.json` 的 `sectors`）：證交所的分類指數有階層，「電子」與
  「化學生技醫療」是彙總類，等於底下幾個細類的總和（實測到小數點後四位一樣）。
  算比重時分母要扣掉彙總類，否則電子被算兩次、半導體會從 36% 被稀釋成 19%。
